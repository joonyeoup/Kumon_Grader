# Elementary HW Grader

A local prototype that grades 1st–6th grade reading/essay homework PDFs using Google Gemini and produces annotated PNGs with ⭕ / ─ marks in the right margin next to each answer. Nothing is uploaded to a server; everything runs on your laptop.

Gemini only returns JSON (coordinates + verdicts + feedback). Python draws the marks on top of the original page PNGs, so student handwriting is never regenerated by the model.

---

## Install

Requires Python ≥ 3.10 and Poppler (for PDF → image conversion).

```bash
# macOS
brew install poppler

# Ubuntu / Debian
sudo apt-get install poppler-utils
```

Then:

```bash
cd Kumon_Grader
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## API key

Get a Gemini API key from https://aistudio.google.com/apikey.

```bash
cp .env.example .env
# edit .env, set GEMINI_API_KEY=...
```

## Assignment folder layout

```
assignments/<name>/
├── rubric.txt                       # plain-text grading criteria (required)
├── answer_key.pdf | .png | .jpg     # teacher's answer key (optional)
└── submissions/
    ├── student_alice.pdf
    ├── student_bob.png
    └── ...                          # .pdf, .png, .jpg, .jpeg all accepted
```

One example rubric is included at `assignments/reading_hw1/rubric.txt`.

- **Answer key is optional.** If no `answer_key.{pdf,png,jpg,jpeg}` exists in the assignment folder, Gemini grades using the rubric alone. Works best when the rubric has clear success criteria for each question.
- **PDFs and images are both fine** for either the answer key or submissions. A single-page PNG / JPG / HEIC is treated as a one-page submission; PDFs are rendered at 200 DPI. HEIC support requires `pillow-heif` (installed by `requirements.txt`). EXIF orientation is respected so iPhone photos come out right-side up.

## Grade submissions

```bash
python grade.py assignments/reading_hw1/
```

Options:

- `--model gemini-2.5-pro` (default) or `--model gemini-2.5-flash` for speed/cost during dev.
- `--workers 3` parallel Gemini calls (default 3).

Output:

```
results/<assignment_name>/
├── progress.json        # resumable state; re-running skips completed students
├── summary.csv          # one row per student
└── <student>/
    ├── page_1_original.png
    ├── page_1_marked.png
    ├── response.json
    └── feedback.txt
```

Re-running the same command skips any student already marked complete.

## View results in the browser

```bash
python viewer.py results/reading_hw1/
```

This opens http://localhost:5000 with a student list; click into each student to see the original page next to the graded page plus per-question feedback.

## Troubleshooting

- **`pdf2image` errors about Poppler.** Install Poppler (see above). On macOS you may need to restart the shell after `brew install poppler`.
- **`GEMINI_API_KEY not set`.** Make sure `.env` exists in the project root and contains `GEMINI_API_KEY=...`, then re-run.
- **Schema validation error from Gemini.** The model occasionally ignores the response schema; just re-run that student (they stay in `progress.json` as failed and get retried).
- **Marks drawn in the wrong spot.** `overlay.py` has a fallback that forces the mark into the right margin when coordinates look out of range. If a whole page looks off, check the PDF's orientation (landscape PDFs can confuse the model — rotate before uploading).
- **`thinking_config` TypeError.** Older `google-genai` versions don't support it; the client silently drops it and keeps going.

## What's not in scope

No accounts, no server, no database, no Gradescope integration, no cost tracking, no handwriting OCR preprocessing. Gemini Vision handles handwriting natively.
